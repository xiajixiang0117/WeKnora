# 实施计划：会话检索执行轨迹

## 目标

为管理员会话管理新增可持久化、按请求查看的 RAG 执行轨迹，覆盖普通 RAG 和 Agent `knowledge_search` 工具；普通聊天接口不暴露该数据。

## 实施步骤

1. 新建 `types.RetrievalExecutionTrace` 及其 JSON 快照 DTO，新增版本化 PostgreSQL `000095` 和 SQLite `000016` 迁移，创建 `retrieval_execution_traces`、租户/会话和租户/请求索引。
2. 新建专用仓储与服务接口，实现按会话获取管理员轨迹摘要、按请求读取详情、请求结束时幂等 upsert，以及会话、消息和租户清理时的关联删除。
3. 新建并发安全的 `RetrievalTraceRecorder`：通过 context 绑定，使用递增序号记录查询改写、每次召回、重排、跳过、失败和取消；序列化时限制每个子查询 500 候选、保留总数和截断标识，并对错误字符串脱敏。
4. 在普通 RAG 的问题理解、检索/查询扩展与重排插件中采集轨迹；将原始分、重排模型分、最终综合分和最终选择状态写入快照。
5. 在 Agent 服务创建 `KnowledgeSearchTool` 时注入请求上下文的同一记录器；为每个工具调用写入独立轮次，采集其多查询、多目标召回、重排和 MMR 后选择。
6. 在 `Handler.executeQA` 建立记录器，传递至服务调用；在正常完成、Agent 完成、请求失败和取消时用不可取消的租户上下文收尾并持久化，且保存失败不影响回答。
7. 扩展管理员会话路由、handler 与前端 API：用量详情只标识是否存在轨迹；新增会话轨迹摘要和单请求详情端点，并在服务层执行管理员和租户范围校验。
8. 扩展 `SessionManagement.vue` 与中英文等现有语言包：在详情抽屉添加请求轨迹列表和按需详情时间线，展示查询增强、召回候选表、重排分数及状态/截断/旧会话状态。
9. 添加后端单元与集成测试（迁移、记录器、RAG、Agent、持久化、清理与鉴权）和前端 API/组件测试；运行 Go 格式化、针对性 Go 测试、前端类型检查/测试及完整相关构建验证。

## 实施顺序与风险控制

先完成数据模型、记录器和测试，再接入两条运行时链路，随后添加管理员 API 与界面。每一层都确保记录失败为旁路错误，绝不影响原有回答链路。候选数据只通过按需详情接口读取，避免会话列表和既有用量接口膨胀。
