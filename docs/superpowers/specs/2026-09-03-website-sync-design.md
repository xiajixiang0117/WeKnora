# 网站知识源：手动差异同步设计

**状态：已确认**  
**日期：2026-09-03**

## 1. 目标与范围

为文档型网站建立可持续维护的知识库来源。管理员配置入口 URL 后，首次可将网站内容分批导入；以后由管理员主动点击“检查更新”，系统自动发现源站新增、修改、失效和抓取失败的页面。系统仅生成差异，绝不在检查阶段自动覆盖或删除知识；管理员审批选中项后才按批次入库或重解析。

首个目标站是 SiFli SDK 一类的静态 Sphinx 文档站。该类站点通常从入口页的侧栏与正文链接可发现完整文档树，但不一定提供 Sitemap。

本功能包含：

- 在文档型知识库中创建和管理 website crawler 数据源。
- 首次全量导入的分批与失败重试。
- 管理员手动触发的扫描、差异生成、内容对比、审批与应用。
- 扫描历史、应用历史与知识库审计。

本功能不包含：

- 定时自动检查更新或自动应用差异。
- 需要登录的网站采集、浏览器自动化登录或绕过访问控制。
- 对 URL 改名的自动“迁移”猜测；改名显示为新增和待下线两项。
- 整站合并为单一大文档。

## 2. 核心决策

| 决策 | 结论 | 原因 |
| --- | --- | --- |
| 入口形态 | 知识库内的“网站同步”页签 | 数据源、文件夹、标签、解析配置和文档状态均属于一个知识库。 |
| 更新触发 | 仅管理员手动点击“检查更新” | 技术部门发布后由管理员在合适窗口核对，避免后台自动扫描与误覆盖。 |
| 更新流程 | 扫描与应用分为两个任务 | 扫描阶段不写知识库；管理员先看差异再决定。 |
| 审批布局 | 差异列表优先，右侧抽屉显示单页对比 | 面对几十至数百个文档时，批量决策效率优先，正文比对按需打开。 |
| 识别页面 | 规范化 URL 为稳定身份，正文哈希决定内容更新 | 同一页能稳定映射到已有知识；无内容变化不重解析。 |
| 失效页 | 默认“待下线”，不自动删除 | 防止源站临时故障或采集规则错误误删已入库内容。 |
| 任务节流 | 应用阶段每批 50 页，低优先级队列 | 避免首次大量入库或大版本更新占满日常解析能力。 |

## 3. 用户流程

### 3.1 创建与首次导入

1. 知识库管理员在“网站同步”创建数据源，填写名称与入口 URL。
2. 管理员配置允许域名、允许路径前缀、排除规则、最大页面数、标签、目标文件夹和解析配置。
3. 系统先发现并预览可导入页面；管理员确认后创建首次扫描批次。
4. 扫描完成后呈现新增差异。管理员勾选页面并选择“应用已选变更”。
5. 应用任务按每批 50 页进入低优先级队列；成功页建立知识条目与网站页面映射。

### 3.2 后续检查更新

1. 管理员在网站同步页点击“检查更新”。
2. 系统发现页面集合、抓取可采集页面、提取正文并生成差异；此阶段不创建或更新任何知识。
3. 扫描批次进入“待审批”，差异分为新增、更新、待下线与失败。
4. 管理员按类型筛选、勾选差异项。点击某行时，在右侧抽屉查看源站链接、旧正文与本次快照的变化片段、抓取信息和建议操作。
5. 管理员点击“应用已选变更”，在确认弹窗中查看预计批数；系统只处理选中项。
6. 结果写入扫描历史与知识库审计日志。失败项保留，可单独重试。

### 3.3 差异决策规则

| 差异 | 默认勾选 | 应用后的结果 |
| --- | --- | --- |
| 新增 | 是 | 创建知识并触发解析与索引。 |
| 更新 | 是 | 用扫描时保存的快照更新对应知识，并触发重解析与索引。 |
| 待下线 | 否 | 管理员显式选择保留、禁用或删除；默认不改变原知识。 |
| 失败 | 否 | 不改变原知识；可在修复后仅重试失败 URL。 |

“本次忽略”仅忽略当前扫描批次。由于知识库保持旧内容，下次检查时该变更会再次出现。要长期排除页面，管理员应更新网站数据源的路径或排除规则。

## 4. 管理端设计

### 4.1 网站同步页签

页签顶部展示：

- 数据源名称、入口 URL、允许路径范围、状态与上次确认时间。
- 已入库页数、最近扫描状态、最近应用结果。
- 主操作“检查更新”；扫描或应用进行中时禁用，避免并发任务。
- “编辑数据源”“查看历史”作为次级操作。

### 4.2 差异列表

扫描完成后显示差异列表，提供“全部 / 新增 / 更新 / 待下线 / 失败”筛选。每一行包含：

- 勾选框和差异类型。
- 页面标题与规范化 URL。
- 变化摘要，例如“正文变化 12%”“新页面”“本轮未发现”“连接超时”。
- 上次入库或检查时间。
- 建议操作和当前审批状态。

列表底部固定批量操作栏，显示已选数量和预计分批数，提供：

- 应用已选变更。
- 忽略本次变更。
- 对失败项重试。
- 导出失败 URL 与原因。

### 4.3 右侧详情抽屉

点击差异行打开抽屉，其中展示：

- 源站链接、规范化 URL、发现路径、抓取时间、响应状态和正文哈希。
- 更新页的旧正文、新正文和变化片段。
- 新增页的本次正文预览。
- 待下线页的最后成功抓取时间与已有知识引用。
- 单项的“本次应用”“本次忽略”与失效页的“保留 / 禁用 / 删除”。

### 4.4 历史记录

每次手动扫描显示开始、结束、操作者、发现数量、审批数量、实际创建/更新/禁用/删除数量和失败原因。管理员可进入历史批次查看其差异与操作结果。

## 5. 后端架构

本功能复用既有数据源框架、异步队列、解析流水线、知识条目、标签、文件夹和审计日志能力。website crawler 连接器实现网页发现、抓取、正文提取和快照生成，但不直接在扫描阶段调用知识入库。

### 5.1 数据模型

现有 data_sources 继续保存通用数据源信息。website crawler 的非机密配置保存在 config.settings：

- seed_urls：一个或多个入口 URL。
- allowed_hosts、path_prefixes、exclude_patterns：采集范围。
- max_pages、batch_size、request_concurrency：资源上限。
- tag_ids、target_folder、process_config：知识入库配置。
- respect_robots：默认 true。

新增三张业务表：

1. web_crawl_pages
   - data_source_id、canonical_url（联合唯一）。
   - knowledge_id（可空）、last_applied_hash、last_seen_scan_id。
   - 上次已应用标题、抓取时间、ETag、Last-Modified 和页面状态。
   - 是“当前知识基线”，只在成功应用后推进。

2. web_crawl_scans
   - 数据源、关联同步日志、发起人、状态、开始/结束时间、页面与差异统计。
   - 状态：scanning、review_ready、applying、completed、partial_failed、canceled。

3. web_crawl_changes
   - 扫描批次、页面或规范化 URL、变更类型、旧/新哈希、内容摘要、抓取错误。
   - 本次快照的存储引用、管理员决策、实际应用状态、对应的任务/错误信息。
   - 快照在审批期间不可变；应用必须使用该快照，而非再次抓取源站。

页面正文快照写入现有对象存储，数据库只保存引用、哈希和用于列表展示的短摘要，防止数据库膨胀。

### 5.2 扫描任务

POST /datasource/:id/scans 创建扫描批次并提交低优先级扫描任务：

1. 验证调用者为知识库所有者或管理员，验证数据源状态，拒绝同数据源已有运行中的扫描或应用。
2. 从入口页、导航与正文链接发现页面；将相对链接解析为绝对 URL。
3. 删除 URL 片段（#anchor）、规范化查询参数和尾随斜杠后去重。
4. 仅保留允许域名与路径范围中的 HTML 页面；忽略静态资源、搜索页、索引页、锚点与不支持内容类型。
5. 对每页执行 SSRF 校验、重定向复核、限速与大小/超时限制，提取主要正文并计算内容哈希。
6. 将本轮结果与 web_crawl_pages.last_applied_hash 对比，保存差异项；本轮未再次发现的已入库页面保存为待下线项。
7. 将扫描批次置为 review_ready 并写入活动审计记录。

### 5.3 应用任务

POST /datasource/:id/scans/:scanId/apply 接受经审批的差异项：

1. 验证批次属于该数据源且状态为 review_ready 或可恢复的 partial_failed。
2. 原子地锁定差异项，转换扫描状态为 applying；重复请求只返回现有任务结果。
3. 按每 50 项分批投递低优先级应用任务。
4. 新增页从快照创建知识；更新页更新已关联知识并复用现有重新解析流水线；失效页按管理员的显式保留、禁用或删除决策执行。
5. 每项成功后才更新 web_crawl_pages 的 knowledge_id、last_applied_hash 与基线元数据。
6. 任何一项失败都保留旧基线与错误；其他批次继续运行。所有批次完成后将扫描标记为 completed 或 partial_failed。

## 6. API

通用数据源接口继续用于创建、编辑、列出、读取和删除网站数据源：

- POST /api/v1/datasource
- GET /api/v1/datasource?kb_id=:kbId
- GET、PUT、DELETE /api/v1/datasource/:id

网站同步新增接口：

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| POST | /api/v1/datasource/:id/scans | 创建手动扫描任务。 |
| GET | /api/v1/datasource/:id/scans | 分页读取扫描历史。 |
| GET | /api/v1/datasource/:id/scans/:scanId | 读取扫描状态、进度与统计。 |
| GET | /api/v1/datasource/:id/scans/:scanId/changes | 分页读取差异，按类型、决策、状态筛选。 |
| POST | /api/v1/datasource/:id/scans/:scanId/apply | 应用已选差异及失效页操作。 |
| POST | /api/v1/datasource/:id/scans/:scanId/cancel | 取消尚未完成的扫描或应用。 |
| POST | /api/v1/datasource/:id/scans/:scanId/changes/retry | 仅重新处理选中的失败项。 |
| GET | /api/v1/datasource/:id/scans/:scanId/failures/export | 下载失败 URL 与原因。 |

所有端点按数据源所属知识库执行 RBAC 校验；扫描、应用、取消、重试仅限所有者或管理员。

## 7. 安全、可靠性与可观测性

- 每一次 URL 访问和每一次重定向都执行 SSRF 校验；拒绝内网、回环、链路本地及 DNS 重绑定目标。
- 默认遵守 robots.txt，并限制同域、路径、最大页数、并发、响应大小、总运行时长与每页超时。
- 只使用静态 HTML 获取；不执行网页 JavaScript。
- 未变化页面跳过解析；失败不会覆盖任何已有知识或内容哈希。
- 同一数据源同一时刻仅允许一个扫描或应用；新的检查请求得到明确的“已有进行中批次”响应。
- 扫描和应用中的单项状态与错误持续记录，任务重启后从未完成差异项恢复。
- 通过既有任务队列面板、同步日志、知识库活动审计和 Langfuse 跟踪扫描、审批、应用链路。

## 8. 验收标准

### 功能

- 能从 SiFli SDK 的 Sphinx 入口页发现相对链接，不依赖 Sitemap。
- 同一页面的锚点链接和等价 URL 只生成一个知识条目。
- 首次导入能以 50 页批次完成，并可仅重试失败页。
- 正文未变的页面不重新解析；正文改变后在审批前不改变知识库。
- 管理员能够看到新增、更新、待下线和失败项，并只应用选中项。
- 待下线页在未明确选择前保留原知识。
- 应用后，历史与审计日志能追踪操作者、选择和每页结果。

### 自动化测试

- Sphinx 相对链接发现、路径白名单、锚点去重、静态资源排除和无 Sitemap 回退。
- URL 规范化、重定向后的 SSRF 再校验、超时、大小限制与 robots 规则。
- 新增、未变、更新、待下线、抓取失败的差异分类。
- 扫描仅生成差异而不调用知识创建或重解析。
- 50 页应用分批、断点恢复、单项失败不推进基线、失败项重试。
- 并发扫描/应用排他性、幂等应用请求和权限边界。
- 差异列表筛选、默认勾选规则、抽屉内容比对和失效页二次确认。

## 9. 交付顺序

1. 建立网页发现与抓取连接器、数据模型及扫描差异任务。
2. 实现扫描历史、差异 API、应用批处理、基线更新和审计。
3. 实现知识库“网站同步”页签、差异列表、详情抽屉和历史。
4. 补齐端到端测试，并以 SiFli SDK 文档站进行人工验收。
