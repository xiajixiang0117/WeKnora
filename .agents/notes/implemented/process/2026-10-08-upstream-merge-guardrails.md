# Agent Note: 上游合并的本地功能护栏

Status: implemented

## Problem

本仓库曾在 2026-09-18 合并官方代码时按文件处理冲突，导致任务队列、检索执行轨迹、嵌入聊天接线、网站抓取入口与翻译等本地功能被覆盖。事后审计和恢复证明，仅依赖当前 diff 或测试文件存在都无法确认用户行为仍完整。

维护者需要在下一次合并官方功能前得到本机可读的功能索引，减少每次从源码重新发现本地契约的成本，同时避免将共享服务器凭据或部署参数写入版本控制。

## Decision

本机忽略的 `AGENTS.md` 增加「上游合并护栏」和本仓库特有功能表。该表以用户行为和跨层边界为单位，列出网站抓取、远程文件、检索轨迹与引用、会话管理、嵌入聊天、任务队列、文件预览以及 CI/CD 的保留规则、主要模块和现有决策记录。

后续官方合并先阅读此索引，再刷新 `upstream` 并在独立集成分支常规合并。冲突按功能契约适配到官方新实现；不整体还原旧文件，不重写已发布的迁移编号，不绕过官方 CSP 与同源鉴权。每次集成仍需记录实际上游 SHA，并执行受影响范围的数据库、后端、前端和笔记校验。

该本机文档不取代版本化 Agent Note。涉及行为、架构、迁移或流程的新决定仍按现有笔记规则记录；本表只承担快速定位和合并检查清单。

## v0.8.2 integration

本次集成在独立分支 `codex/sync-upstream-v0.8.2` 上以普通 merge 合入上游提交 `3e8b0bfc80b845b2d4b2ed683994748741450a97`。冲突解析保留网站抓取、远程文件导入、检索轨迹与最终引用、按 `request_id` 关联的会话、嵌入聊天、任务队列、预览超时和仅手动触发的 Actions 契约，同时接入官方的 MCP 端点字段、上下文压缩点和其他 v0.8.2 功能。

fork 已发布的数据库迁移编号不能重写，否则既有数据库会把不同 SQL 误认为已执行。因此官方 PostgreSQL 新迁移在本仓库顺延为 `000111_skill_served_version`、`000112_message_context_checkpoint`、`000113_messages_session_created_index`；SQLite 顺延为 `000025` 至 `000033`，依次覆盖压缩点、MCP 端点、消息产物、sandbox、技能与环境变量、宿主工作区、IM locale 和消息索引。文档与迁移测试使用该映射，而不是上游原始编号。

本次已完成冲突标记、迁移编号、相关 schema 文档和本笔记的静态核对。数据库、会话处理、聊天管线、智能体以及前端的类型检查、构建和 i18n 校验仍须在创建合并提交前执行；验证结果只以本次命令输出为准。

## Alternatives considered

只在合并时运行完整 `git diff` 可以获得精确的文本差异，也不需要维护额外说明；但它不能表达官方重构后应保留的用户行为，且容易遗漏生产调用链、迁移语义和安全模型的替代实现，因此不采用。

把完整实现细节复制到一个版本化设计文档能让团队共享，但文档会迅速与上游重构脱节，也会增加敏感本机运维信息被提交的风险。保留既有版本化决策笔记作为权威依据，并在被忽略的 `AGENTS.md` 维护简明索引，边界更清晰。

## Consequences

未来合并开始时可以直接获得本地功能范围、不可退化的行为和验证入口，减少以逐文件冲突选择替代设计判断的风险。维护者需要在新增或改变本地功能契约时同步更新本机索引，并照常维护对应 Agent Note。

索引不能证明当前代码、远端上游或共享服务器状态；网络不可用时不得将陈旧的远端跟踪提交称为最新。合并后仍需通过测试和实际 SHA 记录验证。该决定不触发部署，也不修改共享服务器或生产数据库。
