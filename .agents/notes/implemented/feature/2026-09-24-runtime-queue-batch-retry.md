# Agent Note: 平台队列失败任务批量重试

Status: implemented

## Problem

系统管理的运行队列能够查看失败任务，但管理员只能逐条点击立即执行。失败任务较多时，逐条操作成本高，也容易漏掉需要重新触发的任务。

## Decision

失败任务明细在当前已加载的列表范围内增加复选框、全选和批量重试入口。批量重试逐条复用现有的运行任务 `run_now` 接口，因此继续使用原有管理员权限、任务状态校验、审计记录和业务安全边界。批量范围明确限定为当前已加载且允许 `run_now` 的失败任务，不新增后端批量接口，也不把清除失败记录误当作重试。

## Alternatives considered

### 新增后端批量重试接口

没有采用。现有单任务接口已经包含任务是否仍可运行的校验和审计逻辑；前端复用它可以避免批量接口重新实现权限、状态变化和部分失败语义。

### 全选队列中的全部失败任务

没有采用。任务明细采用游标分页，未加载的任务不在浏览器选择状态中；将全选语义扩展到未展示数据会让用户无法确认实际影响范围，也会与列表刷新产生竞态。

## Consequences

管理员可以一次选择当前列表中多个失败任务并重新入队，批量操作结束后列表和队列统计会刷新。部分任务可能在操作前已被删除或状态变化，接口会按单任务返回失败；页面保留失败项的选择并提示成功/失败数量，便于继续处理。批量操作会产生多条既有任务审计记录和多个请求。

## Testing

新增前端交互后运行前端类型检查、生产构建和笔记校验；重点验证全选状态、切换状态清空选择、批量操作成功及部分失败提示。
