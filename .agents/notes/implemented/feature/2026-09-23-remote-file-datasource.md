# Agent Note: 固定 URL 远程文件定时同步

Status: implemented

## Problem

网页爬取连接器将页面转换成 Markdown，不会将网页链接指向的 PDF 二进制交给文件解析器。一次性 URL 导入虽可解析 PDF，但不能定期检查固定文件地址。

## Decision

新增 `remote_file` 数据源，多个非机密文件 URL 保存在 `settings.file_urls`。每个 URL 是独立的资源和稳定外部 ID；首次同步下载原始字节进入文件解析流程，后续按原有数据源调度执行增量同步。每次下载限制 100 MiB，以 SHA-256 内容指纹决定是否重建知识；抓取失败或任一文件解析失败不推进游标，以便下一轮重试。出站请求使用 SSRF 安全客户端及重定向校验。前端只校验 URL 必填并列出文件资源，不调用仅接受凭据的连接测试接口。

## 历史审计

现有 `.agents/notes/implemented/feature/2026-09-22-datasource-cron.md` 与本功能部分重叠：它决定调度复用和网页扫描自动应用，本篇只规定固定文件 URL 的同步与解析，不修改网页扫描语义。其他活跃笔记无此连接器归属。

## Alternatives considered

扩展网页爬取连接器可沿用现有扫描界面和 HTML 基线，但需要在 Markdown 页面与二进制文件间分叉抓取、审阅和应用契约，增加网页行为回归风险，因此采用独立连接器。仅依赖 ETag 或 Last-Modified 可以减少下载流量，但源站可能不返回或错误复用缓存头，不能可靠识别文件变化，因此首版每次下载并比对内容指纹。

## 验证

连接器单测覆盖 URL 去重与 SSRF 拒绝、首次下载、未变化跳过和内容变化重入；注册测试验证容器可用。前端流程测试覆盖创建、资源列表和触发同步。Go 定向测试、前端类型检查和构建、笔记校验共同验证跨模块配置。

## Consequences

固定三个 PDF 地址可配置为一个数据源并设置 cron；网页爬取本身仍处理网页而非 PDF 附件。每次检查消耗完整文件下载流量；超过限制或暂时下载失败会记录同步失败，不会把该次内容标为已同步。首版不自动删除已移除的 URL 对应知识。
