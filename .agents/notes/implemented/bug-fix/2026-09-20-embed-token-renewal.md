# Agent Note: 嵌入问答短期令牌续期

Status: implemented

## Problem

2026-09-20 16:58 的嵌入会话创建返回 401，错误为渠道或令牌无效；16:59 重新交换令牌后创建成功。请求不记录凭据，不能将具体失败令牌与签发记录逐一关联，因此不能断言该次一定是自然过期。

代码存在两个确定缺陷：普通发布令牌在初始化时兑换为 30 分钟短期令牌，之后不续期；安全嵌入宿主虽定期发送新短期令牌，useEmbedBridge 的 bootstrapped 判断却丢弃后续消息。创建会话统一显示失败提示，隐藏了认证失效的实际原因。

## Decision

普通模式按服务端 expires_in 在有效期的 80% 自动兑换新令牌，失败后延迟重试；发送入口检查续期时间，补偿后台标签页定时器被节流。共享进行中的兑换，避免并发续期。只更新令牌，不重建会话或覆盖草稿。

安全模式接收宿主后续提供的新短期令牌，不使用短期令牌自行兑换，也不引入发布令牌降级。组件卸载后取消定时器并忽略迟到的续期响应。

EmbedChatCore 通过 getter 向消息模块提供当前 props.token，避免初始化时的字符串副本导致续期后仍发送旧令牌。发送流程等待 ensureSession 和 nextTick 后读取令牌。

## Alternatives considered

- 延长后端有效期：改动小，减少短期复现，但失效仍会再次发生，且扩大凭据有效窗口。
- 遇到错误要求刷新网页：可通过重新初始化换取令牌，适合作为临时恢复；不能解决长时间停留的正常使用。
- 刷新时完整执行初始化：复用既有流程，但会重新读取历史和改写会话状态，可能覆盖新建草稿。

## Testing

回归测试覆盖自动续期、宿主令牌更新、原会话与草稿保留、续期失败后重试、并发发送共享兑换、卸载后不更新状态，以及消息请求读取续期后的令牌。保持已有延迟创建会话测试通过。另检查前端类型与嵌入来源、语言相关测试。

## Consequences

长时间停留的页面可以续期且保留会话；代价是页面存活期间定期兑换令牌。当前仅完成本地修复，尚未部署或进行线上长时间停留验证。

安全模式仍由宿主负责获取有效新令牌，静态短期令牌本身不能续期。网络中断、渠道禁用或发布令牌被撤销时不能保证自动恢复，也不能无限重放创建请求。
