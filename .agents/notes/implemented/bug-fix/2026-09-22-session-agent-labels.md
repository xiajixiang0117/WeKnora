# Agent Note: 会话管理智能体名称与缺失记录

Status: implemented

## Problem

会话管理复用智能体选择器列表解析名称，但该列表刻意隐藏内部 Wiki 修复与技能安装智能体。回答未记录智能体 ID、智能体已删除、内部智能体未被列出三种情况均显示未知智能体。服务器只读聚合查询确认这三种情况均存在。

## Decision

IM 流式与非流式回答创建时均持久化本次解析出的智能体 ID、所属租户及模型 ID。只读渠道聚合确认 18 条缺少 ID 的回答中，17 条来自企微的 8 个会话。IM 创建消息辅助函数原先未赋值这些字段，是新增缺失记录的直接原因。扩展检索 IM、企微未发现其他归属笔记。

名称查询保留当前租户配置的名称，并从内置注册表补齐缺失的内部智能体。缺少 ID 的回答显示未记录智能体；存在 ID 但无法解析名称显示智能体不可用。无回答的会话显示占位符。混合会话也保留未记录 ID 的回答类别。历史记录不推断、不回填，不扩大跨租户数据访问权限。

## 历史笔记审计

检索会话管理、未知智能体与 session agent：问题展示笔记和上游合并审计与本次部分重叠，分别负责问题关联与合并恢复，不替代本次名称解析决定。

## Alternatives considered

直接扩大普通智能体列表能复用现有查询，但会让内部工具出现在用户选择器，破坏隐藏内部智能体的约束。根据会话配置回填历史回答可减少空值，但同一会话可切换智能体，无法保证历史归属真实。

## 验证

后端 11 项定向测试通过，覆盖 IM 消息身份记录、内部智能体名称、租户名称优先及混合缺失记录；五种语言的 14 项文案检查通过。未部署服务器，尚未验证部署后的企微真实消息。

## Consequences

新 IM 回答保留智能体身份，内部智能体可正常显示名称。删除的自定义智能体仍无法恢复名称；历史缺失记录保留缺失状态。汇总中的空 ID 项表示确有未记录身份的回答，客户端需按缺失记录展示。
